#Computer-Science 

A database is a persistent structured store of data 
A column is called a field 
A row is called a record 
A table is a collection of records and fields 

Flat-file database : 
- No relationship between tables 
- e.g. JSON files 
- Very simple and useful for small non-relational databases 
- Only one entry allowed for each 

Relational database : 
- Tables have relationship 
- Tables are linked using primary and foreign keys 

A primary key is a field that has a unique value for every record in a table e.g. an id 
A foreign key is field that links to a primary key in another table 
A secondary key is an alternative primary key that makes queries quicker e.g. name 
Using a secondary key is also called indexing as it optimises data searching 
A composite key is when 2+ fields are the primary key 

## - Normalisation 

1st Normal form : 
- Have a primary key 
- Each field only has one thing (atomic) 
- All items in a field are of the same data type 

2nd Normal form : 
- Follows 1NF 
- Every key is dependant on the primary key 
- If a table has a composite key all other fields need to depend on all parts of it 

3rd Normal form : 
- Follows 2NF 
- All fields depend only on the primary key 

Normalisation removes duplicated & redundant data 
Makes it easier and more consistent to make changes to a database 
Faster sorting and queries 
Can make queries more complex and slower

## - ACID 

A transaction is a single logical operation on data 
Transaction processing involves all actions taken to complete a transaction in its entirety 
Either entire transaction is processed or not at all 
e.g. money transfer, database updating 

Record Locking : 
- Without record locking, data may be overwritten by simultaneous transactions 
- Record locking prevents two people from accessing a record at the same time 
- Access is denied until transaction complete or cancelled 
- Record locking can cause deadlock when simultaneous transactions block each other's records 

Atomicity : 
- Transaction processed entirely or not at all 
Consistency : 
- Referential integrity maintained 
- Cannot add data to non-existent entry 
Isolation : 
- Transactions do not interfere with one another 
- Concurrent queries are treated as if sequential 
Durability : 
- Complete transactions will remain 
- Unaffected by power outage 
- Held in buffer until transaction complete 

## - SQL 

SQL is a declarative language used to query & update databases 

`SELECT` - which fields to be displayed (`SELECT *` selects all fields) 
`FROM` - which tables to select from 
`WHERE` - precedes search criteria 
e.g. `SELECT name, email FROM user.db WHERE name = "Bob"` 

A wildcard is `%` which can represent any string 
`SELECT name FROM user.db WHERE name LIKE "A%"` will select all names that start with 'A' 
Dates are written with `#` e.g. `SELECT name FROM user.db WHERE dob = #01/01/2007#` 

Search criteria : 
- `=, >, <, !=, >=, <=, AND, OR, NOT` 
- `IN` is like an `OR` statement for many values e.g. `IN (A,B)` is the same as `= A OR = B` 
- `BETWEEN a AND b` defines an inclusive range 
- `IS NULL` checks if empty 
- `LIKE` uses `%` to select all that match e.g. `LIKE "A%"` will select all strings beginning with 'A' 

`JOIN` will join two tables together 
```
SELECT Student.name, Student.age, Teacher.name 
FROM Student 
JOIN Teacher 
ON Student.classId = Teacher.classId 
WHERE Student.age >= 17 
```
This will have the same affect as : 
```
SELECT Student.name, Student.age, Teacher.name 
FROM Student, Teacher 
WHERE Student.classId = Teacher.classId AND Student.age >= 17 
```

The `INSERT` command is used to add a new record to a table 
e.g. `INSERT INTO Student (name, age) VALUES ("Bob", 18)` 

The `DELETE` command will delete a record from a table 
e.g. `DELETE FROM Student WHERE age < 17` 

The command `DROP TABLE Student` will delete the `Student` table
