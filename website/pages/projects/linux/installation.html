Arch Linux Installation Guide

Throughout this guide, the symbol $^\square$ means I am unfamiliar with the specific topic and may revisit it once I learn more.

This page is a broader installation guide for arch linux meant as a direct extension of the official arch linux installation guide, so read the official guide alongside. This guide aims to explain all the terms used and extra things for a newer linux user. Most people say arch linux is not a good first linux distribution to start because it is less user friendly and doesn't come with almost anything pre-built, but now with LLMs it has become much easier to learn independently and once you get comfortable with CLIs (command line interfaces) it's really not that bad. I think arch linux is best for a very modular and custom-tailored operating system (OS), as well as for learning how computers work through using them. I do not think this is an appropriate plug-and-play distribution because any user software needs to be installed manually on a bare installation (this guide), but I have found it very fun to set up and learn how computers manage themselves, and a very comfortable environment for programming.

What is Arch Linux

Arch Linux is a very minimal operating system which is built on top of Linux, a kernel. An operating system is the combination of a kernel and a user space. A kernel manages all hardware and network operations and provides an interface for this with 'system calls'. The user space includes all other software that utilises the hardware and network rather than managing them, including user interfaces, background services and programs with context to the user (text editors, games, browsers etc).

Setup

You can dual boot operating systems, meaning that 2 or more can exist on your machine (e.g. arch linux and windows) and you choose which one to load into when your computer boots up. This means that you can always try linux without immediately needing to migrate your entire workflow. The first thing you want to decide is what to install arch linux onto; an entire drive or a drive partition. A drive partition is where a single drive is divided into multiple logical drives so, even if you only have one drive, you can install multiple operating systems.

Setting up the Drive

If installing onto an entire drive, just back up anything you want to keep to cloud storage or a different drive (everything on the drive will be deleted). If installing onto a drive partition, still back up important files as partitioning a drive carries a risk of data loss in case of a disruption.

Partitioning on Windows

Right click the windows logo and select Disk Management. If the device has not been partitioned yet you will likely see 3 primary partitions (in blue); a couple hundred MB EFI system partition, a letter partition (e.g. C:) slightly smaller than your drive size and a ~1GB recovery partition. The EFI (Extensible Firmware Interface) partition is what boots up windows. Only partition a letter drive. To create a partition, right click the letter drive and select Shrink Volume..., which will open up a menu after querying drive volume. If you don't plan to install many graphical applications or games then 64GB is enough for programming, office work and light gaming (like Minecraft). For a main system with more applications and games, 128GB or 256GB is good. Enter the volume you want to unasign from your letter partition into the menu. A few extra GB will be used later when a new EFI partion and potentially a swap partition are made (explained later). For a school laptop I would recommend between 64 and 128 GB.

Partitioning on Linux

Many common file system partitions (like ext4) do not allow for them to be shrunk while they are running. Therefore, I will explain how to partition using the live environment later on.

Setting up the ISO

An ISO (Internation Organisation for Standardisation) file is just a standardised file format for installations. To install an OS onto a blank drive or partition, a separate medium is required to facilitate the installation. The medium can be either a USB flash drive, an optical disc or a server with PXE. Right now I don't know how PXE works$^\square$, but it seems best either for installing a pre-configured system or for installing onto multiple machines over a network (using netboot rather than ISO), but for a fresh one-time install a flash drive or optical disc seems more appropriate. In this guide I will only be going over the use of a USB medium; maybe in the future I will cover optical discs$^\square$. Note, if using an optical disc a CD will not work as its 700MB capacity is too small for the ISO, so make sure you have at least a single-layer DVD and compatible disc drive.

Downloading the ISO

To download an image (copy of the same file from different locations) of an ISO go to the official downloads page. In this guide I will be installing an image over HTTP, with the links to all the available mirror sites at the bottom of the downloads page. Select a site you want to download the image from, ideally from a reputable source and one close to your country. These links will take you to a list of downloads. There will be two sets of links, the first set being dated and the second set not. The second set is just symbolic links that point to the latest version. As of yet I haven't really dealt with files compressed under .tar$^\square$ so I will be downloading the uncompressed version. It is currently October 2026 so I will be downloading the archlinux-2026.10.01-x86_64.iso file. When downloading over HTTP, it is possible for downloads to be intercepted and a malicious image be provided instead, which is what a checksum is for. A checksum is a hash of a file into a string of fixed length and can be used to quickly confirm that two files are identical. In this guide, I will be assuming that the official website https://archlinux.org has not been compromised, so the checksum provided by it can be trusted. Once I learn more about PGP signatures I will probably make a page on it$^\square$. To perform a checksum on Windows, open a terminal in the same folder as your downloaded image and run Get-FileHash .\archlinux-2026.10.01-x86_64.iso -Algorithm SHA256 (or whatever your downlaoded file is named) to get the sha256 hash. On Linux, run sha256sum archlinux-2026.10.01-x86_64.iso. After this, compare your calculated hash with the one provided on the official arch linux downloads page; if it is the same then the downloaded ISO file is official.

Once downloaded and verified, the ISO needs to be flashed (replacing all contents) onto a medium, so plug in a USB drive or disc drive with a disc into your device. Make sure the disc or USB does not have anything you want to keep because this will be wiped.

Flashing the ISO

The guide on the arch linux page for flashing the ISO onto a USB is already quite complete, showing plenty of different ways on linux with GNU coreutils. In the commands given, a # or $ is to reference permissions as root or normal user respectively, so for commands prefixed with # you should write sudo to use root permissions. Running ls -l /dev/disk/by-id/usb-* will show the id and name of any USB plugged in. This path is a pointer to the the /dev/ path of the USB. For example running this command showed /dev/disk/by-id/usb-USB_DISK_2.0_900058C322CC8B25-0:0 -> ../../sda where the first path points to the actual device path /dev/sda. It is important to check with by-id first because the direct path may change. You may also see partitions of the USB, but make sure to use the non-partitioned path. An example using the cat command (in user bob) is sudo cat /home/bob/Downloads/archlinux-2026.10.01-x86_64.iso > /dev/sda. This works because the cat command outputs all file contents and > writes output onto a given path. The page on arch linux also lists many graphical installation interfaces. Windows also has many graphical and command-line tools to choose from; I will be using Rufus because it is quite a small application. You want to select your USB drive then select the ISO file. For me keeping all the default options works, but if the drive does not boot correctly you may need to change the partition scheme or the image mode (selected after pressing START). The app may prompt for some updates, then will give a warning that all data on the USB will be destroyed.

Booting up the Live Environment

Once the ISO has been flashed onto the USB, you will need to prepare your device for booting into the USB. You will need to turn off secure boot in your device's bootloader menu, because secure boot prevents un-athorised software from booting up on your machine. On Windows you will likely need to turn off fast startup first by opening control panel then going to hardware and sound > change what the power buttons do > change settings that are currently unavailable then turn it off. Entering the bootloader menu is determined by hardware, so you can try to look online for what key your motherboard uses, but common keys include Esccape, Delete, F1, F2 and F10. You should press the key repeatedly right after powering on your machine. Once on the boot menu, navigate through to find secure boot and turn it off then save and exit. Next plug in your USB drive and enter press the same again which should prompt you to select a drive to boot into, and you should see your USB drive. Once selected you should enter the arch linux live environment ready for installation.

Installation

The first thing you should see is a menu with different setup options, so select whichever is appropriate, but the default is the Arch Linux install medium. Once selected, the live environment will boot up on your machine and print all the checks onto the screen. After this a terminal should appear saying root@archiso ~ # at the bottom. This format will appear at every new command line telling you the following: the user (user is root in this environment); the name of the device (archiso in my case); the current directory (~ means "the current user's home directory", so for root the home directory is /root); and finally the permissions, which as stated before includes # and $ for root and user permission respectively.

Using Arch Linux

Before continuing with the installation, this heading aims to explain some things about Linux to make the installation more understandable.

File System

The Linux file system is a monolithic tree structure, meaning the entire system is within a single root directory / called root that branches out into sub-directories and files. Each file or directory is represented by a node (called an inode in this case) which ties it to its parent directories (the one it is a part of) and child directories / files (the ones that are part of it). This hierarchy is written using forward slashes to separate the levels. For example, a user directory called "bob" lies in the "home" directory which is part of the root directory; this is written as /home/bob. Files are not organised inside of hardware as this would require constant re-organising, so the abstracted nodes associated with files and directories act as pointers to retain the structure. A folder on Windows is a directory.

A path name starting with / means it starts from root (e.g. the path /home/bob/Downloads/potato.png is an image in the bob user's download directory relative to root); a path name starting with a directory name means it starts from the current working directory (e.g. the same image relative to the bob user directory would be Downloads/potato.png). These can be described as absolute and relative file paths respectively. Within a directory, the name . and the name .. refer to the directory and the directory's parent respectively. If you are in the Downloads directory as per the previous examples, . would be /home/bob/Downloads and .. would be /home/bob.

Mounting is when an external file system is attached to the current file system. A useful application is to mount the file system of an external drive to access the drive's contents within the current system. This is an essential step of the installation process described later.

Below is a very basic overview of the first-level directories (those within root) in a Linux system :

  • /boot - OS boot files, including the kernel and EFI
  • /dev - Device files, including interfaces to device drivers that control hardware [short for devices]
  • /home - Where all personal user directories are
  • /root - User directory of the root user, not to be confused with root which is just /
  • /tmp - Directory whose contents are wiped when device is restarted, useful for debug logs
  • /mnt - Temporary manual mounting point
  • /etc - System-wide configuration files
  • /bin - User commands and utilities [short for binaries]
  • /sbin - System admin commands [short for system binaries]
  • /lib & /lib64 - Libraries needed for /bin and /sbin
  • /usr - Where most of installed binaries, libraries and documentation are. The previous library and binary directories are often symbolic links to directories within this one where the actual data is stored [short for user as probably initially for user programs]
  • /var - Data that changes during runtime like logs
  • /opt - Another directory often for self-contained software packages
  • /media - Mount point for removable media like USBs or DVDs
  • /run - Another directory with temporary contents about runtime state since boot
  • /srv - Meant for files that your device servers to others, like website code for server
  • /sys - A virtual file system (files are generated on demand) used to change system settings
  • /proc - Also a virtual file system for processes and kernel information
  • /lost+found - Where tools put recovered file stuff

Console

A shell is a program that provides a text-based interface to the user for executing system programs. This includes interpreting input commands and arguments to run appropriate programs, and . A console (or terminal) is a command line interface (CLI) built into all linux systems that allows the bare minimum interface to it, and is text-only. A shell interprets input commands and arguments to run the appropriate programs. It allows you to input one string at a time to be interpreted by the system, which will then respond by printing strings back onto the console. In Linux, the default consoles are called teletype (tty) consoles, and are the main interface provided by a vanilla arch installation.

Later on you can install console apps that are dynamic, but the bare console just prints monospaced characters.

Using the Console

Here I will go over some essential command line utilities (commands) that will be used in the installation process, and are also very useful. Commands are words typed directly into the terminal followed by options and arguments. The arguments are the inputs to the command, such as a specific file path, and the options change what the command do, like showing different details. Options begin with at least one hyphen and are conventionally put before the arguments in a command string. There can also be multiple option forms for the same option, most notably a short and long form, conventionally prefixed by a single and double hyphen respectively. For example, a common option is -v or --version which displays the version of a software package. Some options also require arguments, often in the form --option1=arg1. Single hyphen options can be put together in one hyphen e.g. -a and -b can be passed as -ab.

  • man - This command is short for manual and when given a different command as an argument, it will display a manual for that command. This is very useful for learning what commands do, how they can be used and what options are available. I encourage you to use this often when finding out about new commands, however, it may be insufficient at times if you don't know the terminology used. I recommend that you read the manual page for all the commands listed below.
  • info - This is similar to man, but where man gives a short overview of all options, info gives a very detailed explanation of each command.
  • ls - This command lists all contents of a directory. If only ls is entered, all nodes that are children of the directory you are currently in will be printed to console. It can be given any directory path on your system as an argument to print its respective contents. The most useful options are: -a, which lists all nodes, including hidden ones (all those beginning with a period); -l, which lists node details including type, permissions, size on disk etc; and -h, which displays size on disk in a "human-readable" format as opposed to bytes (this is measured in exbibytes which uses orders of magnitude of $2^{10}$ (1024), so a kibibyte (KB) is 1024 bytes, a mibibyte (MB) is 1024 kibibytes, etc). Note, using ls -lah will show all directories as being 4 kibibytes because it does not look within those directories so displays the size of the inode. To see the size of directories use the next command.
  • du - This shows the size on disk of the argument directory (or current if not given) and all directories at a greater depth than it. To show something useful you should either do du -sh for human readable and summary (only given directory is shown), or du -h --max-depth=n where $n\geq0$. Doing du / will flood your console with every directory on your system (a lot). Running du on large directories like root and /usr will often take a little time as all the sizes are determined. Some directories may require root permissions so do sudo du -sh / to see total system storage.

Live Environment Setup

To see battery percentage if on a laptop, use the command cat /sys/class/power_supply/BAT0/capacity.

In the live environment there is a keybind of Alt + left / right arrow key to switch between tty consoles where text editors or the installation guide can be opened (the login is root). There are a few terminal-based text editors available to edit files; nano, vim and mcedit. I would advise against mcedit because it burned my retinas and against vim because the keybinds are not beginner-friendly (if you get stuck in vim press ": + q + Enter"). In nano you open a file with nano /path/to/file.extension, save with CTRL + S and exit with CTRL + X. At the bottom all the controls are listed where ^ means CTLR and M stands for the modifier key which is ALT. Default console keymap is a US keyboard, so if you want to change it find your keymap with localectl list-keymaps. I use a UK keyboard and my keymap is called uk so then I enter loadkeys uk. If the font size is too small or large you can see the available fonts by entering ls /usr/share/kbd/consolefonts and change the font with setfont <font>. A good font scale is one where listing all fonts takes up a bit over half the screen - for me the default ter-132b font does this. If your network uses DHCP then the following steps should work, but if not then you can check the arch linux guide as I do not know much about networks yet$^\square$.

You should now connect to the internet using the iwctl command. First enter iwctl with no arguments to enter an interactive prompt (basically a command line only in the context of the program). For wireless connection (not sure about wired$^\square$), enter device list which should print a station mode device (mine is called wlan0, so I will use this name in the following examples). Then do station wlan0 scan followed by station wlan0 get-networks which should print available networks. To connect to a network station wlan0 connect "SSID", which will then prompt for a network password, then enter exit to leave the interactive prompt. Enter the command ping -c 3 ping.archlinux.org, which will send a ping to the website 3 which lets you verify an internet connection. Default timezone is UTC; to change enter timedatectl list-timezones, find your correct one (mine is Europe/London), then set it with timedatectl set-timezone Europe/London. Verify with timedatectl. With an internet connection you can now also access the official guide in a text format by entering Installation_guide.

Setting up the System

The first thing to do is to create partitions and asign their types. First use lsblk to determine the name of your drive (mine is nvme0n1), then do cfdisk /dev/nvme0n1 to enter an interface; use arrow keys to navigate and enter to use option. There is a help page for more options. Now you want to decide how many operating systems you are planning to have and how big you want your swap file. GRUB seems to be ideal for dual-booting because it allows for a separated EFI partitions for Windows (because it likes to overwrite the EFI partition), and for this only a few 100MB are needed per OS, so a 512MB partition is probably fine (I had 3 on a 260MB partition previously). If using systemd-boot, you may want a 1GB EFI partition, not too sure, but the recommended size on the guide is 1GB. As for a swap file, if you probably don't need it if you are browsing, programming and light gaming on 8GB RAM, playing medium games (Minecraft) on 16GB RAM, playing high-end games on 32GB RAM. On my setup I have gone with a ~100GB main partition (because of dodgy past partitioning), a 1GB EFI partition and a 4GB swap partition. Next you will need to apply the appropriate file types of Linux filesystem, EFI system and Linux swap. To save these changes you need to click the write button, say yes then you can quit. Using fdisk -l /dev/nvme0n1 you can verify the partitions exist and that they are the correct sytem type (this isn't their filesystem yet, only their labelled type for booting). Take a note of the partition number of each. You will now need to set the file system of each partition: for the main Linux filesystem partition, set it with mkfs.ext4 /dev/partition; for the EFI partition (mine is p8) mkfs.fat -F 32 /dev/efi_partition; and for swap file (mine is p9) mkswap /dev/swap_partition. Now you want to mount the file systems by doing mount /dev/root_partition /mnt and mount --mkdir /dev/efi_partition /mnt/boot and enablie your swap partition with swapon /dev/swap_partition.

In /etc/pacman.d/mirrorlist you will find all available HTTPS mirrors for pacman, the top links are used first, so if you have a preference move one you want to the top. Now onto installing pacman and some essential packages. For a bare functional install you will probably want the base, linux and linux-firmware packages. You will also want a network package so you don't get stuck offline, I recommend network manager because it natively handles ethernet and has a text GUI. You will probably also want a text editor like nano for now. Then, depending on your CPU, you will want intel-ucode or amd-ucode for security updates. So the command I will be using is pacstrap -K /mnt base linux linux-firmware intel-ucode networkmanager nano. Other packages can be installed a bit later. This command will then begin installing the packages onto your disk.

Next you will need to generate a file system table by genfstab -U /mnt >> /mnt/etc/fstab, which tells the Linux system how to mount what filesystems. Check the result with cat to see if it looks about right. Next you want to change root into your the drive by doing arch-chroot -S /mnt. Now changes you make to files here will be on the main system. First you will want to set the timezone again, but you can't do it the same way as your system won't have access to processes yet, so instead use the command ln -sf /usr/share/zoneinfo/Europe/London /etc/localtime which links /etc/localtime to that timezone file. To save the time to the ahardware clock, run hwclock --systohc. To set up language formatting, edit the file /etc/locale.gen, uncomment the appropriate locales, then run locale-gen to generate them. Create a file at /etc/locale.conf to set the language, for example I am using british english so I add the line LANG=en_GB.UTF-8. Also update console keyboard at /etc/vconsole.conf with the same keymap code as the first time, so I will add the line KEYMAP=uk. If you added a keymap to console, run mkinitcpio -P, which regenerates an initialisation process to include the new config files (not essential as this is done anyway by pacman).

To name your device (to be recognisable on a network), add the name to /etc/hostname. This will also be displayed on default terminal command prefixes. Do systemctl enable NetworkManager so that network manager turns on on boot-up. The command passwd creates a password for the root user, i.e. a password that gives access to the entire system, so make this secure. You can change this password at anytime by typing passwd as root user or sudo passwd root as another user. If you forget your password, you will need to boot up a live ISO again, mount your filesystem, chroot into it and do passwd, just like you did now.

Setting up GRUB bootloader

I will be using GRUB on this machine because it is pretty much the most compatible bootloader, but I may make guides for some other bootloaders later$^\square$. As a reminder, this setup is for UEFI bootloader systems. This setup also assumes you are still in the chroot environment. Firstly, install the necessary grub packages with pacman pacman -S grub efibootmgr, then install grub to your /boot directory (which is your EFI partition) using grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB, then generate config files with grub-mkconfig -o /boot/grub/grub.cfg. Running efibootmgr -v should verify that grub is installed correctly. Assuming grub got installed correctly, your system should now be installed with the bare minimum to be usable (as a user operating system). You can now exit from chroot, enter shutdown now to shut down the computer, then boot it back up and it should boot into grub. Select arch linux and you should see a bare tty prompting for login. The only login currently set up is root with your root password.
