Arch Linux Installation Guide

Throughout this guide, the symbol $^\square$ means I am unfamiliar with the specific topic and may revisit once I learn more.

This page is a broader installation guide for arch linux meant as a direct extension of the official arch linux installation guide, so read the official guide alongside. This guide aims to explain all the terms used and extra things for a newer linux user. Most people say arch linux is not a good first linux distribution to start because it is less user friendly and doesn't come with almost anything pre-built, but now with LLMs it has become much easier to learn independently and once you get comfortable with CLIs (command line interfaces) it's really not that bad. I think arch linux is best for a very modular and custom-tailored operating system (OS), as well as for learning how computers work by using them.

Setup

You can dual boot operating systems, meaning that 2 or more can exist on your machine (e.g. arch linux and windows) and you choose which one to load into when your computer boots up. This means that you can always try linux without immediately needing to migrate your entire workflow. The first thing you want to decide is what to install arch linux onto; an entire drive or a drive partition. A drive partition is where a single drive is divided into multiple logical drives so, even if you only have one drive, you can install multiple operating systems.

Setting up the Drive

If installing onto an entire drive, just back up anything you want to keep to cloud storage or a different drive (everything on the drive will be deleted). If installing onto a drive partition, still back up important files as partitioning a drive carries a risk of data loss in case of a disruption.

Partitioning on Windows

Right click the windows logo and select Disk Management. If the device has not been partitioned yet you will likely see 3 primary partitions (in blue); a couple hundred MB EFI system partition, a letter partition (e.g. C:) slightly smaller than your drive size and a ~1GB recovery partition. The EFI (Extensible Firmware Interface) partition is what boots up windows. Only partition a letter drive. To create a partition, right click the letter drive and select Shrink Volume..., which will open up a menu after querying drive volume. If you don't plan to install many graphical applications or games then 64GB is enough for programming, office work and light gaming (like Minecraft). For a main system with more applications and games, 128GB or 256GB is good. Enter the volume you want to unasign from your letter partition into the menu. A few extra GB will be used later when a new EFI partion and potentially a swap partition are made (explained later). For a school laptop I would recommend between 64 and 128 GB.

Partitioning on Linux

Many common file system partitions (like ext4) do not allow for them to be shrunk while they are running. Therefore, I will explain how to partition using the live environment later on.

Setting up the ISO

An ISO (Internation Organisation for Standardisation) file is just a standardised file format for installations. To install an OS onto a blank drive or partition, a separate medium is required to facilitate the installation. The medium can be either a USB flash drive, an optical disc or a server with PXE. Right now I don't know how PXE works$^\square$, but it seems best either for installing a pre-configured system or for installing onto multiple machines over a network (using netboot rather than ISO), but for a fresh one-time install a flash drive or optical disc seems more appropriate. In this guide I will only be going over the use of a USB medium; maybe in the future I will cover optical discs$^\square$. Note, if using an optical disc a CD will not work as its 700MB capacity is too small for the ISO, so make sure you have at least a single-layer DVD and compatible disc drive.

Downloading the ISO

To download an image (copy of the same file from different locations) of an ISO go to the official downloads page. In this guide I will be installing an image over HTTP, with the links to all the available mirror sites at the bottom of the downloads page. Select a site you want to download the image from, ideally from a reputable source and one close to your country. These links will take you to a list of downloads. There will be two sets of links, the first set being dated and the second set not. The second set is just symbolic links that point to the latest version. As of yet I haven't really dealt with files compressed under .tar$^\square$ so I will be downloading the uncompressed version. It is currently October 2026 so I will be downloading the archlinux-2026.10.01-x86_64.iso file. When downloading over HTTP, it is possible for downloads to be intercepted and a malicious image be provided instead, which is what a checksum is for. A checksum is a hash of a file into a string of fixed length and can be used to quickly confirm that two files are identical. In this guide, I will be assuming that the official website https://archlinux.org has not been compromised, so the checksum provided by it can be trusted. Once I learn more about PGP signatures I will probably make a page on it$^\square$. To perform a checksum on Windows, open a terminal in the same folder as your downloaded image and run Get-FileHash .\archlinux-2026.10.01-x86_64.iso -Algorithm SHA256 (or whatever your downlaoded file is named) to get the sha256 hash. On Linux, run sha256sum archlinux-2026.10.01-x86_64.iso. After this, compare your calculated hash with the one provided on the official arch linux downloads page; if it is the same then the downloaded ISO file is official.

Once downloaded and verified, the ISO needs to be flashed (replacing all contents) onto a medium, so plug in a USB drive or disc drive with a disc into your device. Make sure the disc or USB does not have anything you want to keep because this will be wiped.

Flashing the ISO

The guide on the arch linux page for flashing the ISO onto a USB is already quite complete, showing plenty of different ways on linux with GNU coreutils. In the commands given, a # or $ is to reference permissions as root or normal user respectively, so for commands prefixed with # you should write sudo to use root permissions. Running ls -l /dev/disk/by-id/usb-* will show the id and name of any USB plugged in. This path is a pointer to the the /dev/ path of the USB. For example running this command showed /dev/disk/by-id/usb-USB_DISK_2.0_900058C322CC8B25-0:0 -> ../../sda where the first path points to the actual device path /dev/sda. It is important to check with by-id first because the direct path may change. You may also see partitions of the USB, but make sure to use the non-partitioned path. An example using the cat command (in user bob) is sudo cat /home/bob/Downloads/archlinux-2026.10.01-x86_64.iso > /dev/sda. This works because the cat command outputs all file contents and > writes output onto a given path. The page on arch linux also lists many graphical installation interfaces. Windows also has many graphical and command-line tools to choose from; I will be using Rufus because it is quite a small application. You want to select your USB drive then select the ISO file. For me keeping all the default options works, but if the drive does not boot correctly you may need to change the partition scheme or the image mode (selected after pressing START). The app may prompt for some updates, then will give a warning that all data on the USB will be destroyed.

Booting up the Live Environment

Once the ISO has been flashed onto the USB, you will need to prepare your device for booting into the USB. You will need to turn off secure boot in your device's bootloader (BIOS / UEFI) menu, because secure boot prevents un-athorised software from booting up on your machine. On Windows you will likely need to turn off fast startup first by opening control panel then going to hardware and sound > change what the power buttons do > change settings that are currently unavailable then turn it off. Entering the bootloader menu is determined by hardware, so you can try to look online for what key your motherboard uses, but common keys include Esccape, Delete, F1, F2 and F10. You should press the key repeatedly right after powering on your machine. Once on the boot menu, navigate through to find secure boot and turn it off then save and exit. Next plug in your USB drive and enter press the same again which should prompt you to select a drive to boot into, and you should see your USB drive. Once selected you should enter the arch linux live environment ready for installation.

Installation

The first thing you should see is a boot menu, so select whichever is appropriate but the default is the Arch Linux install medium. Once selected the live environment will boot up on your machine and print all the checks onto the screen. After this a terminal should appear saying root@archiso ~ # at the bottom. This format will appear at every new command line telling you the following: the user (user is root in this environment); the name of the device (archiso in my case); the current directory (~ means "the current user's home directory", so for root the home directory is /root); and finally the permissions, which as stated before includes # and $ for root and user permission respectively.

Live Environment Setup

In the live environment there is a keybind of Alt + left / right arrow key to switch between tty consoles where text editors or the installation guide can be opened (the login is root). There are a few terminal-based text editors available to edit files; nano, vim and mcedit. I would advise against mcedit because it burned my retinas and against vim because the keybinds are not beginner-friendly (if you get stuck in vim press ": + q + Enter"). In nano you open a file with nano /path/to/file.extension, save with CTRL + S and exit with CTRL + X. At the bottom all the controls are listed where ^ means CTLR and M stands for the modifier key which is ALT. Default console keymap is a US keyboard, so if you want to change it find your keymap with localectl list-keymaps. I use a UK keyboard and my keymap is called uk so then I enter loadkeys uk. If the font size is too small or large you can see the available fonts by entering ls /usr/share/kbd/consolefonts and change the font with setfont <font>. A good font scale is one where listing all fonts takes up a bit over half the screen - for me the default ter-132b font does this. If your network uses DHCP then the following steps should work, but if not then you can check the arch linux guide as I do not know much about networks yet$^\square$.
