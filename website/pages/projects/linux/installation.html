Arch Linux Installation Guide

This guide is for installing a bare-minimum system, and later guides will go over tools I like to use.

This page is a broader installation guide for arch linux meant as a direct extension of the official arch linux installation guide, so read the official guide alongside. This guide aims to explain all the terms used and extra things for a newer linux user. Most people say arch linux is not a good first linux distribution to start because it is less user friendly and doesn't come with almost anything pre-built, but now with LLMs it has become much easier to learn independently and once you get comfortable with CLIs (command line interfaces) it's really not that bad. I think arch linux is best for a very modular and custom-tailored operating system (OS), as well as for learning how computers work through using them. I do not think this is an appropriate plug-and-play distribution because any user software needs to be installed manually on a bare installation (this guide), but I have found it very fun to set up and learn how computers manage themselves, and a very comfortable environment for programming.

What is Arch Linux

Arch Linux is a very minimal distribution of Linux, which means it is an operating system built on top of Linux (a kernel). An operating system is the combination of a kernel and a user space. A kernel manages all hardware and network operations and provides an interface for this with 'system calls'. The user space includes all other software that utilises the hardware and network rather than managing them, including user interfaces, background services and programs with context to the user (text editors, games, browsers etc).

There are many distributions (distros) of Linux; popular ones include Ubuntu, Debian, Arch, Fedora etc. Each distribution provides different default user space software based on its developers' philosophy. The main Arch philosophies can be found on their website. Arch is rolling-release, meaning programs are updated when the next version comes out, as opposed to waiting for specified stable releases. A base Arch installation is defined by the base package, which includes the following features :

  • C Runtime - Standard C libraries for basic system functionalities and system calls.
  • Filesystem - Generates and contains the file layout of the system.
  • Package Manager - Manages software packages. Arch uses pacman.
  • Core Utilities - A collection of programs that perform the basic system actions; handling file relations, navigating the system, archiving etc. Arch uses GNU core utils, a standardised set of commands.
  • Shell - A program and scripting language that allows the user to input commands and arguments to execute programs in various ways.
  • Initialisation System - The process which the kernel starts, and is responsible for initialising the rest of the system. Also handles device detection and logins. Arch uses systemd.
  • Networking Tools - Diagnose network.
  • Compression Tools - Needed for packages.
  • Localisation - language translation tool.
  • Users - Permission assignment to different logins.

Setup

You can dual boot operating systems, meaning that 2 or more can exist on your machine (e.g. arch linux and windows) and you choose which one to load into when your computer boots up. This means that you can always try linux without immediately needing to migrate your entire workflow. The first thing you want to decide is what to install arch linux onto; an entire drive or a drive partition. A drive partition is where a single drive is divided into multiple logical drives so, even if you only have one drive, you can install multiple operating systems.

Setting up the Drive

If installing onto an entire drive, just back up anything you want to keep to cloud storage or a different drive (everything on the drive will be deleted). If installing onto a drive partition, still back up important files as partitioning a drive carries a risk of data loss in case of a disruption.

Partitioning on Windows

Right click the windows logo and select Disk Management. If the device has not been partitioned yet you will likely see 3 primary partitions (in blue); a couple hundred MB EFI system partition, a letter partition (e.g. C:) slightly smaller than your drive size and a ~1GB recovery partition. The EFI (Extensible Firmware Interface) partition is what boots up windows. Only partition a letter drive. To create a partition, right click the letter drive and select Shrink Volume..., which will open up a menu after querying drive volume. If you don't plan to install many graphical applications or games then 64GB is enough for programming, office work and light gaming (like Minecraft). For a main system with more applications and games, 128GB or 256GB is good. Enter the volume you want to unasign from your letter partition into the menu. A few extra GB will be used later when a new EFI partion and potentially a swap partition are made (explained later). For a school laptop I would recommend between 64 and 128 GB.

Partitioning on Linux

Many common file system partitions (like ext4) do not allow for them to be shrunk while they are running. Therefore, I will explain how to partition using the live environment later on.

Setting up the ISO

An ISO (Internation Organisation for Standardisation) file is just a standardised file format for installations. To install an OS onto a blank drive or partition, a separate medium is required to facilitate the installation. The medium can be either a USB flash drive, an optical disc or a server with PXE. Right now I don't know how PXE works$^\square$, but it seems best either for installing a pre-configured system or for installing onto multiple machines over a network (using netboot rather than ISO), but for a fresh one-time install a flash drive or optical disc seems more appropriate. In this guide I will only be going over the use of a USB medium; maybe in the future I will cover optical discs$^\square$. Note, if using an optical disc a CD will not work as its 700MB capacity is too small for the ISO, so make sure you have at least a single-layer DVD and compatible RW disc drive.

Downloading the ISO

To download an image (a copy of the same file from different destinations) of an ISO go to the official downloads page. In this guide I will be installing an image over HTTP, with the links to all the available mirror sites at the bottom of the downloads page. Select a site you want to download the image from, ideally from a reputable source and one close to your country. These links will take you to a list of downloads. There will be two sets of links, the first set being dated and the second set not. The second set is just symbolic links that point to the latest version. As of yet I haven't really dealt with files compressed under .tar$^\square$ so I will be downloading the uncompressed version. It is currently October 2026 so I will be downloading the archlinux-2026.10.01-x86_64.iso file. When downloading over HTTP, it is possible for downloads to be intercepted and a malicious image be provided instead, which is what a checksum is for. A checksum is a hash of a file into a string of fixed length and can be used to quickly confirm that two files are identical. In this guide, I will be assuming that the official website https://archlinux.org has not been compromised, so the checksum provided by it can be trusted. Once I learn more about PGP signatures I will probably make a page on it$^\square$. To perform a checksum on Windows, open a terminal in the same folder as your downloaded image and run Get-FileHash .\archlinux-2026.10.01-x86_64.iso -Algorithm SHA256 (or whatever your downlaoded file is named) to get the sha256 hash. On Linux, run sha256sum archlinux-2026.10.01-x86_64.iso. After this, compare your calculated hash with the one provided on the official arch linux downloads page; if it is the same then the downloaded ISO file is an exact copy.

Once downloaded and verified, the ISO needs to be flashed (meaning copying to and replacing all contents) onto a medium, so plug in a USB drive or disc drive with a disc into your device. Make sure the disc or USB does not have anything you want to keep because this will be wiped.

Flashing the ISO from Linux

The guide on the arch linux page for flashing the ISO onto a USB is already quite complete, showing plenty of different ways on linux with GNU coreutils. In the commands given, a # or $ is to reference permissions as root or normal user respectively. Running ls -l /dev/disk/by-id/usb-* will show the id and name of any USB plugged in. This path is a pointer to the the /dev/ path of the USB. For example running this command showed /dev/disk/by-id/usb-USB_DISK_2.0_900058C322CC8B25-0:0 -> ../../sda where the first path points to the actual device path /dev/sda. It is important to check with by-id first because the direct path may change. You may also see partitions of the USB, but make sure to use the non-partitioned path. An example using the cat command (in user bob) is sudo cat /home/bob/Downloads/archlinux-2026.10.01-x86_64.iso > /dev/sda. This works because the cat command outputs all file contents and > writes output onto a given path. The page on arch linux also lists many graphical installation interfaces.

Flashing the ISO from Windows

Windows also has many graphical or command-line tools to choose from; I will be using Rufus because it is quite a small application. You want to select your USB drive then select the ISO file. For me keeping all the default options works, but if the drive does not boot correctly you may need to change the partition scheme or the image mode (selected after pressing START). The app may prompt for some updates, then will give a warning that all data on the USB will be destroyed.

Booting up the Live Environment

Once the ISO has been flashed onto the USB, you will need to prepare your device for booting into the USB. You will need to turn off secure boot in your device's bootloader menu, because secure boot prevents non-verified systems from booting up on your machine. On Windows you will likely need to turn off fast startup first by opening control panel then going to hardware and sound > change what the power buttons do > change settings that are currently unavailable then turn it off. Entering the bootloader menu is determined by hardware, so you can try to look online for what key your motherboard uses, but common keys include Esccape, Delete, F1, F2, F10 and F12. You should press the key repeatedly right after powering on your machine. Once on the boot menu, navigate through to find secure boot and turn it off then save and exit. Next plug in your USB drive and press the same key to enter the boot menu, which should show your USB drive as one of the boot options. Once selected, you should enter the arch linux live environment ready for installation.

This guide only goes over how to set up a UEFI bootloader, not a BIOS, because I do not have any machines that use BIOS$^\square$.

Installation

The first thing you should see is a menu with different setup options, so select whichever is appropriate, but the default is the Arch Linux install medium. Once selected, the live environment will boot up on your machine and print all the checks onto the screen. After this, a terminal should appear saying root@archiso ~ # at the bottom. This format will appear at every new command line telling you the following: the user (user is root in this environment); the name of the device (archiso in my case); the current directory (~ means "the current user's home directory", so for root the home directory is /root); and finally the permissions, which as stated before includes # and $ for root and user permission respectively.

Using Arch Linux

Before continuing with the installation, this heading aims to explain some things about Linux to make the installation more understandable.

File System

The Linux file system is a monolithic tree structure, meaning the entire system is within a single root directory / called root that branches out into sub-directories and files. Each file or directory is represented by a node (called an inode in this case) which ties it to its parent directories (the one it is a part of) and child directories / files (the ones that are part of it). This hierarchy is written using forward slashes to separate the levels. For example, a user directory called "bob" lies in the "home" directory which is part of the root directory; this is written as /home/bob. Files are not organised inside of hardware as this would require constant re-organising, so the abstracted nodes associated with files and directories act as pointers to retain the structure. A folder on Windows is a directory.

A path name starting with / means it starts from root (e.g. the path /home/bob/Downloads/potato.png is an image in the bob user's download directory relative to root); a path name starting with a directory name means it starts from the current working directory (e.g. the same image relative to the bob user directory would be Downloads/potato.png). These can be described as absolute and relative file paths respectively. Within a directory, the name . and the name .. refer to the directory and the directory's parent respectively. If you are in the Downloads directory as per the previous examples, . would be /home/bob/Downloads and .. would be /home/bob, so the image would be at ./potato.png or ../Downloads/potato.png.

Mounting is when an external file system is attached to the current file system. A useful application is to mount the file system of an external drive to access the drive's contents within the current system. This is an essential step of the installation process described later.

Below is a very basic overview of the first-level directories (those within root) in a Linux system :

  • /boot - OS boot files, including the kernel and EFI
  • /dev - Device files, including interfaces to device drivers that control hardware [short for devices]
  • /home - Where all personal user directories are
  • /root - User directory of the root user, not to be confused with root which is just /
  • /tmp - Directory whose contents are wiped when device is restarted, useful for debug logs
  • /mnt - Temporary manual mounting point
  • /etc - System-wide configuration files
  • /bin - User commands and utilities [short for binaries]
  • /sbin - System admin commands [short for system binaries]
  • /lib & /lib64 - Libraries needed for /bin and /sbin
  • /usr - Where most of installed binaries, libraries and documentation are. The previous library and binary directories are often symbolic links to directories within this one where the actual data is stored [short for user as probably initially for user programs]
  • /var - Data that changes during runtime like logs
  • /opt - Another directory often for self-contained software packages
  • /run - Another directory with temporary contents about runtime state since boot
  • /srv - Meant for files that your device servers to others, like website code for server
  • /sys - A virtual file system (files are generated on demand) used to change system settings
  • /proc - Also a virtual file system for processes and kernel information
  • /lost+found - Where tools put recovered file stuff

Shell

As described before, a shell is a program and scripting language that allows the user to input commands and arguments to execute programs in various ways. A console, or a terminal, is the command line interface (CLI) that displays the user's interaction with the shell. In linux, the default consoles are called teletype (tty) consoles, and are the only graphical output on a base install.

I will go over some essential command components that will be used in the installation process, and that are also very useful. Commands are words typed directly into the terminal followed by options (/ flags) and arguments. The arguments are the inputs to the command, such as a specific file path, and the options change what the command do, like showing different details. Options begin with at least one hyphen and are conventionally put before the arguments in a command string. There can also be multiple option forms for the same option, most notably a short and long form, conventionally prefixed by a single and double hyphen respectively. For example, a common option is -v or --version which displays the version of a software package. Some options also require arguments, often in the form --option1=arg1. Single hyphen options can be put together in one hyphen e.g. command -a and command -b can be passed as command -ab.

Linux processes have 3 standard streams; standard in, standard out and standard error. The standard standard in in shell is keyboard input and its standard out and error is the terminal. Streams can be redirected using certain operators. The > operator redirects standard out to a given file, useful for creating logs or writing long outputs to a file for easier reading (note, this overwrites the file's content). The pipe character | directs one command's standard out to a second command's standard in, commonly used to quickly filter a long output.

  • man - This command is short for manual and when given a different command as an argument, it will display a manual for that command. This is very useful for learning what commands do, how they can be used and what options are available. I encourage you to use this often when finding out about new commands, however, it may be insufficient at times if you don't know the terminology used.
  • info - This is similar to man, but where man gives a short overview of all options, info gives a very detailed explanation of each command.
  • ls - This command lists all contents of a directory. If only ls is entered, all nodes that are children of the directory you are currently in will be printed to console. It can be given any directory path on your system as an argument to print its respective contents. The most useful options are: -a, which lists all nodes, including hidden ones (all those beginning with a period); -l, which lists node details including type, permissions, size on disk etc; and -h, which displays size on disk in a "human-readable" format as opposed to bytes (this is measured in exbibytes which uses orders of magnitude of $2^{10}$ (1024), so a kibibyte (KB) is 1024 bytes, a mibibyte (MB) is 1024 kibibytes, etc). Note, using ls -lah will show all directories as being 4 kibibytes because it does not look within those directories so displays the size of the inode. To see the size of directories use the du command.
  • pwd - This stands for "print working directory" and ... prints your working directory.
  • cd - This stands for "change directory", and changes your working directory to a argument path.
  • cat - Prints an entire argument file's content to standard out.
  • mount - Used to mount argument 1 node to argument 2 path. To unmount, the command is umount <mounted path>.
  • mkdir - Creates a new directory at the argument path.
  • touch - Creates a new file at the argument path.
  • du - This shows the size on disk of the argument directory (or current if not given) and all directories at a greater depth than it. To show something useful you should either do du -sh for human readable and summary (only given directory is shown), or du -h --max-depth=n where $n\geq0$. Doing du / will flood your console with every directory on your system (a lot). Running du on large directories like root and /usr will often take a while. Some directories may require root permissions so do sudo du -sh / to see total system storage.

If you ever want to terminate a command currently being run you can press CTRL + C.

Packages

Packages are a standardised format for software. This makes software modular which allows it to be be verified easily and be used as a dependency easily, reducing code duplication. A package manager helps the user perform software updates from verified sources and manage the relations between packages (like dependencies). Package repositories are where package managers get package code, sources, versions etc. Arch's package manager is called pacman, and it has two official package repositories: core and extra. There are also unofficial repositories managed by the community, the main one being the arch user repository (AUR). Of course, software can still be downloaded and installed manually, but this will need to be self-managed.

Live Environment Setup

To see battery percentage on a laptop, use the command cat /sys/class/power_supply/BAT0/capacity.

In the live environment there is a keybind of Alt + left / right arrow key to switch between tty consoles, where text editors or the installation guide can be opened (the login is root). There are a few terminal-based text editors available to edit files; nano, vim and mcedit. I would advise against mcedit because it burned my retinas, and against vim because the keybinds are not beginner-friendly (if you get stuck in vim press escape a few time then ": + q + Enter"). In nano you open a file with nano <path>, save with CTRL + S and exit with CTRL + X. At the bottom all the controls are listed where ^ means CTRL and M- stands for the modifier key which is ALT.

The default console keymap is a US keyboard, so if you want to change it find your keymap with localectl list-keymaps. I use a UK keyboard and my keymap is called uk so then I enter loadkeys uk. If the font size is too small or large you can see the available fonts by entering ls /usr/share/kbd/consolefonts and change the font with setfont <font>. A good font scale is one where listing all fonts takes up a bit over half the screen - for me the default ter-132b font does this.

If your network uses DHCP then the following steps should work, but if not then check the arch linux guide as I do not know much about networks yet$^\square$. Now you need to connect to the internet using iwctl. First enter iwctl with no arguments to enter an interactive prompt (a command line in the context of the program). For wireless connection (wired should connect automatically I think$^\square$), enter device list which should print a station mode device (mine is called wlan0, so I will use this name in the following examples). Then do station wlan0 scan followed by station wlan0 get-networks, which should print all available networks. To connect to a network, enter station wlan0 connect <SSID> which will then prompt for a network password, then enter exit to leave the interactive prompt. Enter the command ping -c 3 ping.archlinux.org, which will send a ping to the website 3 times and verifies an internet connection.

The default timezone is UTC. to change it, enter timedatectl list-timezones, find your one (mine is Europe/London), then set it with timedatectl set-timezone Europe/London. Verify with timedatectl. With an internet connection you can also access the official online guide in a text format by entering Installation_guide.

Setting up the System

Partitions

The first thing to do is to create partitions and assign their types. Use lsblk to determine the name of your drive (mine is nvme0n1), and (if you want) perform a health check with smartctl -a /dev/drive_name. Do cfdisk /dev/drive_name to enter an interface; use arrow keys to navigate and enter to select (there is a help page). Now you want to decide how many operating systems you are planning to have and how big you want your swap file. GRUB is probably better for dual-booting because it allows for a separate EFI partition for Windows (Windows likes to overwrite the EFI partition). Systemd-boot is smaller and probably better for a single-OS system. For either one, you'll want a 512MB or 1GB EFI partition. A swap file is backup RAM in case your system's RAM runs out. If the processes running on your system exceed the ammount of RAM and there is no swap file, the system will terminate high-use systems. You don't want to rely on swap because it is slower and will cause your drive to wear down faster, so only designate between 0-8GB for it.

On my setup I have gone with a ~100GB main partition (because of dodgy past partitioning), a 1GB EFI partition and a 4GB swap partition. On the interface, you can delete partitions and create new ones, then you will need to apply the appropriate file types of Linux filesystem, EFI system and Linux swap. To save these changes you need to click the write button, say yes then you can quit. Use fdisk -l /dev/drive_name to verify the changes have been made and that they are the correct sytem type (this isn't their filesystem yet, only their labelled type for booting). Take a note of the name of each partition, typically the drive name followed by p1, p2 etc.

You will now need to set the file system of each partition: for the main Linux filesystem partition, set it with mkfs.ext4 /dev/root_partition; for the EFI partition, mkfs.fat -F 32 /dev/efi_partition; and for swap file mkswap /dev/swap_partition. Now you want to mount the file systems by doing mount /dev/root_partition /mnt and mount --mkdir /dev/efi_partition /mnt/boot, then enable your swap partition with swapon /dev/swap_partition.

System

In /etc/pacman.d/mirrorlist you will find all available HTTPS mirrors for pacman, the top links are used first, so if you have a preference move the ones you want to the top. Now you install the system. For the bare-minimum functional install you need the base, linux and linux-firmware packages. You will also want a network package so you can use the internet; I recommend network manager because it natively handles ethernet and has a text user interface (TUI). You will probably also want a text editor like nano, although you can use raw shell if you want. Then, depending on your CPU, you will want intel-ucode or amd-ucode for security updates. So, the command I will be using is pacstrap -K /mnt base linux linux-firmware intel-ucode networkmanager nano. Other packages can be installed later. This command will then begin installing the packages onto your drive.

Next you will need to generate a file system table with genfstab -U /mnt >> /mnt/etc/fstab, which tells the Linux system how to mount your other partitions when it boots. Check the result to see if your partitions are assigned the right roles. Next, you want to "enter your system's context" by changing root into your the drive using arch-chroot -S /mnt. Changes you make to these files will be on the main system.

First, you will want to set the timezone again, but you can't do it the same way because your system isn't running processes yet, so instead use the command ln -sf /usr/share/zoneinfo/Europe/London /etc/localtime (use the same region you used before) which links /etc/localtime to that timezone file. To save the time to the hardware clock, run hwclock --systohc.

You will also need to set up your locale again. To do this, open the file /etc/locale.gen and uncomment (remove the hash) the appropriate locales, then run locale-gen to generate them (this only generates them but does not select). Then, create a file at /etc/locale.conf to select a locale, and enter the locale you uncommented as LANG=<locale>. For example, I am using british english so I add the line LANG=en_GB.UTF-8. Also set the console keyboard at /etc/vconsole.conf by entering KEYMAP=<language> using the same keymap code you used for the live environment (KEYMAP=uk for me). Finally, run mkinitcpio -P to regenerate an initialisation process to include the new config files.

To name your device (to be recognisable on a network as), enter a name at /etc/hostname. This will also be displayed on default terminal command prefixes. Do systemctl enable NetworkManager (if using network manager) so that network manager turns on at boot-up. The command passwd creates a password for the current user. Enter passwd to create a root password, i.e. the password that gives access to the entire system (so make this secure). You can change this password at any time by typing passwd as root user. If you forget your password, you will need to boot up a live ISO again, mount your system, chroot into it and do passwd, just like you did now.

Setting up bootloader

As a reminder, this setup assumes a UEFI bootloader. You should still be in the chroot environment.

systemd-boot

Enter bootctl install, then create a file at /boot/loader/loader.conf and write :

default arch.conf
timeout 3
console-mode max
editor no

You can leave out the timeout line to boot instantly (if you want to enter boot menu, press space repeatedly as your computer powers on). The console mode line uses the highest resolution for the menu. The editor line disables the editor which can allow somebody to bypass your system login. For the next step, create a file at /boot/loader/entries/arch.conf, then identify your root partition's UUID with blkid /dev/root_partition. To make things easier, you can do blkid -s UUID -o value /dev/root_partition >> /boot/loader/entries/arch.conf to write it straight into the file. Fill out the rest of the file :

title   Arch Linux
linux   /vmlinuz-linux
initrd  /intel-ucode.img
initrd  /initramfs-linux.img
options root=UUID=<root UUID> rw

The 3rd line is if you installed your processor's package (mine is intel). This file tells systemd-boot what to initialise and how. To verify, enter bootctl status, move down to the default boot loader entry and check the details look reflect what you entered.

GRUB

First, install the necessary grub packages with pacman -S grub efibootmgr, then install grub to your /boot directory (which is your EFI partition) using grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB. Next, generate config files with grub-mkconfig -o /boot/grub/grub.cfg, and verify it is installed correctly using efibootmgr -v.

Done

Now you are done, so exit the chroot with exit, unmount the drive with umount -R /mnt then reboot. On boot-up, you should now see a tty prompting for login. The only login currently is root; if you want to set up users, got to my users guide.
